# MillionHoursTimer

MillionHoursTimer は、指定したアプリケーションの作業時間を自動で記録する Windows 向けの常駐アプリです。開いているファイルごとの作業時間の記録、履歴のグラフ表示、[Toggl](https://toggl.com/) への記録の送信ができます。日々の活動記録やモチベーション管理にお役立てください。

# 動作環境

Windows 10 / 11 (64bit)。.NET のインストールは不要です。

# インストール

[Releases](https://github.com/kanchi0914/MillionHoursTimer/releases) から次のどちらかをダウンロードしてください。

- **インストーラー版** (`MillionHoursTimer-win-Setup.exe`)
  実行するとインストールされ、スタートメニューとデスクトップにショートカットができます。管理者権限は不要です。新しいバージョンが出たら、アプリの中から更新できます。アンインストールは Windows の「設定 → アプリ」から行えます。
- **ポータブル版** (`MillionHoursTimer-win-Portable.zip`)
  解凍したフォルダを好きな場所に置いて、`MillionHoursTimer.exe` から起動してください。

「Windows によって PC が保護されました」と表示された場合は、「詳細情報」→「実行」を選んでください。

### 終了方法

×ボタンを押しても終了せず、タスクトレイに常駐します。**終了するときは、タスクトレイのアイコンを右クリック →「終了」**を選んでください。
設定画面の「Windows の起動時に自動的に起動する」をオンにすると、PC の起動時に自動で記録を始めます。

# 旧バージョン (v1) からの移行

v2 を初めて起動すると、旧バージョン (MHTimer v1.x) のデータを探して取り込む画面が表示されます。あとから取り込む場合は「ファイル → 旧バージョンのデータを取り込む」を選んでください。

- 取り込まれるもの: 登録アプリ、累計時間、ファイル別の累計時間、ファイル拡張子、Toggl 連携の設定 (アプリごとのプロジェクトとタグ)、各種設定。Toggl の API キーは Toggl 2.0 では使えないため引き継ぎません
- 旧バージョンのデータは書き換えません。取り込んだ時点の旧データの複製も、新しいデータフォルダの `legacy-backup` に保存します。
- 旧バージョンには「いつ作業したか」の記録がないため、これまでの累計時間は日付なしで取り込みます (履歴のグラフには表示されません)。
- バイナリ版 (zip) を使っていて自動で見つからない場合は、`MHTimer.exe` があるフォルダを指定してください。

> [!IMPORTANT]
> **インストーラー版の旧バージョンは、アンインストールすると data フォルダ (記録データ) を削除します。** 旧バージョンをアンインストールするのは、v2 に取り込んでからにしてください。
> また、旧バージョンと v2 を同時に起動すると時間が二重に記録されます。v2 は起動時に旧バージョンが動いていないか確認し、終了するよう案内します。

# 使い方

## 記録するアプリの登録

記録したいアプリの実行ファイル (.exe) またはショートカット (.lnk) を、画面にドラッグ＆ドロップしてください。「ファイル → アプリを追加」から選ぶこともできます。
記録中のアプリは、一覧で背景がピンク色になります。

## 計測方法

「設定 → 記録設定」で、次の3つから選べます。

| 計測方法 | 内容 |
|---|---|
| 起動しているアプリを全て計測する | バックグラウンドで動いているものも含めて計測します。 |
| 最小化していないアプリのみ計測する (既定) | ウィンドウを最小化しているアプリは計測しません。 |
| アクティブウィンドウのみ計測する | いま操作しているウィンドウのアプリだけを計測します。 |

一定時間 PC の操作がなかったときは、**最後に操作した時点**で計測を止めます (「無操作判定時間」で変更できます)。スリープ中も計測しません。

## ファイル別作業時間の記録

**タイトルバーにファイル名と拡張子が表示されるアプリ**では、ファイルごとの作業時間を記録できます。一覧のアプリを右クリック →「ファイル拡張子を設定」で、拡張子を半角スラッシュ区切りで設定してください。

例) イラスト系ソフト: `.gif/.jpg/.jpeg/.png/.bmp/.ico/.tif/.tiff/.tga/.psd/.psb/.sai`

記録はアプリを右クリック →「ファイル別の作業時間」(またはダブルクリック) で確認できます。複数の項目を選んで1つにまとめることもできます。

タイトルバーが `ファイル名 - アプリ名` の形で表示されるアプリは、「設定 → ファイル設定 → ハイフン区切りをファイル名の取得に利用する」(既定でオン) で、拡張子を設定しなくても記録できます。
Photoshop など、一度名前を付けて保存しないとタイトルにファイル名が出ないソフトもあります。ファイル名でデータを区別しているので、途中でファイル名を変えると別のファイルとして記録されます。

### 項目が増えすぎるとき (ブラウザなど)

ブラウザのようにタイトルがページごとに変わるアプリでは、ファイル別の項目がどんどん増えていきます。次の機能で整理できます。

- **自動削除**: 「ファイル別の作業時間」画面の「自動削除の設定」で、最後に作業した日から指定した日数がたった項目を自動で削除できます (アプリごとに設定、既定はオフ)。累積が指定した分数以上の項目は残すこともできます。削除は起動時と日付が変わったときに行います。
- **ロック**: 消したくない項目は、右クリック →「ロックする」でロックできます。ロックした項目は自動削除と「全て削除」の対象になりません。
- **ファイル別の最小記録時間**: 「設定 → ファイル設定」で、これより短い作業をファイル別に記録しないようにできます。一瞬だけ開いたページが項目として残るのを防げます。

どれもファイル別の記録だけが対象で、アプリ全体の作業時間は変わりません。旧バージョンから取り込んだ記録 (最終作業日がないもの) は自動削除しません。

### CLIP STUDIO PAINT の場合

CLIP STUDIO PAINT はメインウィンドウのタイトルにファイル名を表示しないため、そのままではファイル名を取得できません。**「ページ管理」ウィンドウか「ストーリーエディター」を、メインウィンドウから切り離して (フローティングして) 別ウィンドウで表示**すると記録できます。「ファイル名をスペースで区切る」をオンにしておくことをおすすめします (既定でオン)。

「最小化していないアプリのみ」「アクティブウィンドウのみ」で計測している場合、切り離したウィンドウを最小化するとファイル名が記録されなくなります。これを避けるには「ファイル名表示ウィンドウの計測条件を無視する」をオンにしてください。

## 履歴とグラフ

「表示 → 履歴とグラフ」で、日ごと・月ごとの作業時間をアプリ別の積み上げグラフで確認できます。

# 記録データについて

データは `%APPDATA%\MillionHoursTimer` (例: `C:\Users\(ユーザー名)\AppData\Roaming\MillionHoursTimer`) に保存されます。「ファイル → データフォルダを開く」で開けます。アプリをアンインストールしても消えません。
バックアップは「ファイル → データをバックアップ」か、このフォルダごとコピーしてください。

```
MillionHoursTimer\
├─ settings.json        設定
├─ apps.csv             登録アプリの一覧 (並び順が画面の表示順)
├─ file_locks.csv       ロックしたファイル別の項目
├─ records\
│   ├─ apps\2026-10.csv   アプリごとの作業記録 (月ごと)
│   └─ files\2026-10.csv  ファイルごとの作業記録 (月ごと)
├─ toggl_log.csv        Toggl への送信状況
├─ toggl.key            Toggl の API キー (暗号化済み)
├─ current.json         計測中の作業 (異常終了したときの復旧用)
├─ icons\  logs\  legacy-backup\
```

作業記録は1回の作業が1行の CSV (BOM 付き UTF-8) で、テキストエディタや Excel でそのまま開けます。

```csv
start,end,seconds,process,app_name,session_id
2026-10-29 21:03:12,2026-10-29 22:41:50,5918,CLIPStudioPaint,CLIP STUDIO PAINT,3f9a1c0b2e7d
```

| 列 | 内容 |
|---|---|
| start / end | 作業の開始・終了日時。日付をまたいだ作業は日ごとの行に分けます。 |
| seconds | 実際に計測した秒数。**合計時間はこの列で計算します** (一時的に対象外だった時間は含まないので、end - start より短いことがあります)。 |
| process | アプリのプロセス名 (実行ファイル名から .exe を除いたもの) |
| app_name | 記録した時点の表示名 |
| file | (files のみ) ファイル名 |
| session_id | 同じ作業を表す ID |

- **手で編集できます。** 起動中に編集しても自動で読み直します。行を追加・削除したり、seconds を直したりすると合計時間に反映されます。start と end があれば seconds は空でも構いません。
- Excel で開いている間は記録を書き込めないため、アプリ内に溜めておいて閉じた後に書き込みます。Excel で上書き保存して文字コードや日付の形式が変わっても読み込めます (次に書き込むときに元の形式に戻します)。
- 列を追加した場合、その列はアプリがファイルを書き直すときに消えます。
- 旧バージョンから取り込んだ累計は `legacy.csv` に、start / end が空の行として入っています。

# Toggl との連携

[Toggl](https://toggl.com/) にアカウントを作り、次の手順で連携してください。

1. ブラウザで Toggl にログインし、[設定画面](https://focus.toggl.com/settings) で **API キー** (`toggl_sk_` で始まるもの) を作成してコピーする。キーは作成したときにしか表示されません
2. 「設定 → Toggl 連携」の API キー欄に貼り付ける
3. Toggl にログインしたときのアドレスバーの URL (`https://focus.toggl.com/数字/workspaces/数字/...`) を URL 欄に貼り付けて「認証」を押す。記録はこの URL のワークスペースに送ります
4. 下の一覧で、Toggl に記録したいアプリの「連携」にチェックを入れ、必要ならプロジェクトとタグを選ぶ

旧 Toggl Track の **API Token** (英数字 32 文字) は使えません。旧バージョンから取り込んだ場合も、Toggl 2.0 の API キーを設定し直してください。

「連携」にチェックを入れたアプリは、作業が終わったときに Toggl に記録します。「最低送信時間」より短い作業は送りません。ネットワークの不調などで送れなかったものは、次に送れるときに自動で再送します。

# 注意事項

- **このアプリで発生したいかなる不具合に関しても、開発者は一切の責任を負いません。使用は自己責任でお願いします。**
- PC への負担が気になる場合は「設定 → 記録設定 → 計測間隔」を長くしてください。
- 管理者権限で実行している場合、ドラッグ＆ドロップでのアプリの登録はできません (Windows の仕様)。「ファイル → アプリを追加」を使ってください。
- アプリによってはうまく記録できない場合があります。

バグ報告やご意見は [Issues](https://github.com/kanchi0914/MillionHoursTimer/issues) にお願いします。

# 開発者向け

必要なもの: [.NET 10 SDK](https://dotnet.microsoft.com/download) のみ (Visual Studio は不要です。VS Code や Rider で開発できます)。

```sh
dotnet build MillionHoursTimer.slnx          # ビルド
dotnet test MillionHoursTimer.slnx           # テスト
dotnet run --project src/MillionHoursTimer -- --data-dir ./tmp-data   # 本物のデータを使わずに起動
```

| ディレクトリ | 内容 |
|---|---|
| `src/MillionHoursTimer.Core` | 計測ロジック・CSV の読み書き・旧データの移行・Toggl API。画面や Windows API に依存しないのでテストしやすい |
| `src/MillionHoursTimer` | WPF の画面、タスクトレイ、Windows API (ウィンドウの列挙・無操作時間・自動起動・DPAPI)、Velopack による更新 |
| `tests/MillionHoursTimer.Core.Tests` | Core のテスト (xUnit) |

起動オプション: `--data-dir <フォルダ>` データの保存先を変える / `--minimized` ウィンドウを出さずにタスクトレイで起動する (自動起動で使用)

### リリース

`v2.0.0` のようなタグを push すると、GitHub Actions ([.github/workflows/build.yml](.github/workflows/build.yml)) がテスト・ビルドし、[Velopack](https://velopack.io/) でインストーラーとポータブル版を作って Releases に公開します。手元で作る場合:

```sh
dotnet tool restore
dotnet publish src/MillionHoursTimer -c Release -r win-x64 --self-contained -o publish -p:Version=2.0.0
dotnet vpk pack --packId MillionHoursTimer --packVersion 2.0.0 --packDir publish --mainExe MillionHoursTimer.exe --icon src/MillionHoursTimer/Resources/app.ico --outputDir releases
```
